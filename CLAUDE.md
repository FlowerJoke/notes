# notes: Levi's HM study notes as PDF + website

Public repo `FlowerJoke/notes`, published with GitHub Pages at https://flowerjoke.github.io/notes/ (branch `main`, root, `.nojekyll`). Classmates view or download the PDFs there.

## How it works
- `tools/create-pdf` is the only code (Python 3, stdlib). It is symlinked as `~/.local/bin/create-pdf`.
- Source of truth for the notes: the Obsidian vault `~/Levi/Main/Local/Studium/Obsidian/Semester 1/<Fach>/Notes/*.md`. **Only the `Notes` folder is exported** (not Übungen, Konzepte, Vorlesungen).
- `create-pdf <Fach>` / `create-pdf all`: converts each note to PDF (pandoc + xelatex, one PDF per note), writes it to `<Fach>/<note>.pdf` in this repo, rebuilds `index.html`, `<Fach>/index.html` and `README.md`, then commits and pushes. Flags: `--no-push` (export and rebuild only), `-o <dir>` (plain export elsewhere, no site, no push, single subject).
- Obsidian handling in `convert()`: `![[x.pdf#page=N&rect=l,b,r,t]]` embeds become cropped images via `pdftoppm` (rect origin is bottom-left, verified); `![[Note]]` embeds are inlined; wikilinks become plain text; `$$\begin{align}..$$` loses the `$$` (LaTeX rejects the nesting); headings directly after a line get a blank line; empty notes are skipped; PDFs of notes that no longer exist are moved to the Trash (`gio trash`).
- Decisions by Levi: slide crops from the lectures are included; the lecture PDFs themselves are NOT published. No disclaimer text on the site. Publishing is automatic (every run pushes).

## Rules for working here
- This repo is public. Never add the lecture PDFs, exercises, solutions, credentials or personal data.
- Use the personal GitHub account `FlowerJoke`, not the work account `FlowerJoke-MI` (`gh auth token --user FlowerJoke` for API calls). Commits use the GitHub noreply email set in this repo's git config; do not change it.
- Never delete files permanently; use `gio trash`.
- `README.md`, `index.html` and `<Fach>/index.html` are generated by `build_site()`. Edit the script, not the output.
- Ask Levi before changing what gets published.

## Needs
`pandoc`, `texlive-xetex` (+ recommended collections), `poppler-utils` (`pdftoppm`, `pdfinfo`) on Fedora.

## Auto-run when the Obsidian vault or a Laborbuch is pushed (added 2026-10-23, Levi's request)
- The vault moved on 2026-10-29 to `~/Levi/Main/Local/Studium/Obsidian` (`VAULT` in `tools/create-pdf`); the old `~/Levi/Main/Local/Obsidian Vault` no longer exists.
- The vault is a git repo (remote `obsidian` -> `FlowerJoke/Obsidian`, pushed by the obsidian-git plugin). Its untracked `.git/hooks/pre-push` only does `touch ~/.local/state/notes-pdf.trigger` (never blocks the push).
- Obsidian is a Flatpak (no pandoc/xelatex, no host access), so it cannot run `create-pdf` itself. The systemd user units `~/.config/systemd/user/notes-pdf.path` (watches the trigger file) and `notes-pdf.service` (waits 20 s, then runs `create-pdf all`) do it on the host. Logs: `journalctl --user -u notes-pdf.service`.
- Tested end to end: hook -> service -> PDFs rebuilt -> pushed. If the vault is ever re-cloned, re-create the hook; the units live outside the repos.

## Laborbuch (`tools/sync-laborbuch`)
- Symlinked as `~/.local/bin/sync-laborbuch`. Copies (repo -> targets, never back) the READMEs of the HM GitLab repos `~/Levi/Main/Local/Studium/Grundlagen der Rechnersysteme/laborbuch-N_*/` (`README.md` + `images/`). Those repos stay where they are (GitLab remote, HM git identity); `documentation*` and `artefacts/`, `*.cv` are not copied.
- Copy 1 (private): `Studium/Obsidian/Semester 1/Grundlagen der Rechnersysteme/Laborbuch/Laborbuch N/` (README + images + `Arbeitsblatt*.pdf`). Not called `Notes`, so `create-pdf` ignores it.
- Copy 2 (public): `Grundlagen der Rechnersysteme/Laborbuch/Laborbuch N.pdf` (README, images embedded) and `Laborbuch/Arbeitsblatt Praktikum N.pdf` (worksheet, copied as is), shown in its own "Laborbuch" section by `build_site()`. It lives in a subfolder because `create-pdf` trashes every PDF directly in `<Fach>/` that is not one of its notes.
- Math: the README in each Laborbuch repo is converted **in place** to Obsidian math (`$x$`, `$$`; HM's template has GitLab `$`x`$`), because Levi edits it in Obsidian. This is the only write into those repos and stays uncommitted by me (Levi commits and pushes to GitLab himself); pandoc reads `$x$` fine. Confirmed 2026-10-18: HM accepts this notation and GitLab renders it correctly, so the converted README is the final form. Nothing needs converting back before a push.
- When Levi says he cloned a new `laborbuch-N`: run `sync-laborbuch` right away. It installs the hook there and converts that repo's README in place to the Obsidian notation (the `$x$` / `$$` form), so he edits it in Obsidian without further changes and pushes to GitLab as is. Every run installs a `pre-push` hook (`.git/hooks/pre-push`, untracked) in each Laborbuch repo. Since 2026-10-29 it does not run `sync-laborbuch` itself but touches `~/.local/state/notes-pdf.trigger` (same trigger as the vault hook), so `git push` to GitLab starts the systemd service -> `create-pdf all`: copies README, images and worksheet of ALL Laborbuch repos to the vault, exports all Laborbuch PDFs and all notes, rebuilds the site and pushes to GitHub. Never blocks the push; a new `laborbuch-N` gets the hook after its first manual run.
- `create-pdf "Grundlagen der Rechnersysteme"` and `create-pdf all` run `sync-laborbuch --no-push` first (vault copy, Laborbuch PDFs, hooks); the publish that follows pushes everything. With `-o <dir>` only `--vault-only` runs (nothing public). Added 2026-10-22 on Levi's request ("do it when I run create pdf").
- Worksheets: the HM worksheet PDF of each Laborbuch lives in its repo folder as `Arbeitsblatt Praktikum N.pdf` (placed by hand). `sync-laborbuch` adds `Arbeitsblatt*.pdf` to the repo's local `.git/info/exclude` (so it can never be committed to GitLab), copies it into the vault's `Laborbuch N/` folder AND into the notes repo's `Laborbuch/` folder, so it is published on the website as its own entry. **Changed 2026-10-29 on Levi's explicit request** (before: vault only, never published, because it is HM material); this overrides the "no exercises" rule for these worksheets only.
- Flags: `--no-push`, `--vault-only` (nothing public). Re-run after changing a README; PDFs of repos that no longer exist are trashed.
- Decision by Levi (2026-10-16): publish everything as is (name, CircuitVerse link, unfinished Laborbuch 2 included), it is for friends. This overrides the "no personal data" rule for these PDFs only.

## Known quirks
- LaTeX writes a timestamp into each PDF, so every run produces a new commit even if the notes are unchanged.
- A note linking to a PDF name that does not exist in the vault shows "not found" in the PDF.
- Empty notes are skipped, and then their old PDFs count as stale and are trashed. A subject whose notes are all empty disappears from the site. Currently the case for `Einführung in die Programmierung` (both notes emptied by Levi on purpose, 2026-10-16); it returns as soon as a note has content again. Do not restore the old content.
